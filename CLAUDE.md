# Инструкции Claude для проекта «1С-Хлеб»

## Цель

Помогать развивать систему приёма хлебных накладных: веб-прототип и локальный
Windows-коннектор к 1С «Торговое предприятие» 7.0.53.2.

## Перед любой работой

1. Прочитай `README.md`, `docs/Проект_автоматизации_1С_хлеб.md` и `docs/Текущий_статус.md`.
2. Проверь `git status`, если репозиторий был клонирован.
3. Не перезаписывай чужие изменения и не выполняй разрушительные Git-команды.
4. Пиши по-русски, если пользователь не попросил иначе.

## Непреложные правила безопасности 1С

- По умолчанию только читай 1С.
- Никогда не отправляй `POST`, `PATCH` или `DELETE` в `http://localhost/khleb1c/`.
- Не запускай `connector/test-create-unposted.ps1` и
  `connector/start-test-create-unposted.cmd`, если пользователь в текущей задаче явно не разрешил
  тестовую запись.
- Даже при таком разрешении сначала проверь, что цель — `khleb1c_test`,
  `default.vrd` указывает на `C:\Baze_Test_Hleb`, а резервная копия подтверждена.
- Не проводи тестовый документ: он должен оставаться `Posted = false`.
- Не копируй в репозиторий базы 1С, выгрузки, пароли, токены или диагностику с бизнес-данными.
- Не коммить `connector/business-data.local.json`: это единственное место для реальных
  GUID, выбранного документа и состава тестовой накладной. В Git остаётся только
  `connector/business-data.example.json` с заглушками.
- На рабочем компьютере создай локальный файл копированием шаблона. Сначала заполни
  поставщика по безопасной выгрузке `catalog-match`, затем параметры тестовой накладной
  по `test-write-preflight/source-document.json`. Перед записью покажи пользователю
  итоговые суммы и дождись отдельного явного разрешения.

## Первичная установка

Если есть доступ к PowerShell, запусти из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1
```

Скрипт должен проверить Git и Node.js, выполнить `npm ci`, а затем запустить безопасные тесты.
Если доступа к командам нет, попроси пользователя запустить `Установить.cmd` двойным щелчком.

## Команды проверки

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

Веб-часть отдельно:

```powershell
Set-Location .\web
npm.cmd ci
npm.cmd run lint
npm.cmd test
```

Не запускай коннекторы 1С в рамках обычной проверки пакета.

## Границы проекта

- Не добавляй личные материалы WorkHub.
- Не коммить `node_modules`, сборки, `.env`, диагностические папки коннектора и резервные копии.
- Изменяй только файлы, нужные для текущей задачи.
- После правок запускай только релевантные проверки и показывай пользователю фактические результаты.
